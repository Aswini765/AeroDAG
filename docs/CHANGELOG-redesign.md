# AeroDAG Redesign & Hardening Changelog (Phases 0–5)

This changelog documents every major issue identified, the architectural fix applied, and the automated test guarding each invariant across Phases 0 through 5.

| Phase | Problem Found | Fix Applied | Guarding Test |
|---|---|---|---|
| **Phase 0** (Baseline Invariants & Provenance) | The application presented mock data as verified live inventory, used silent default dates for ambiguous inputs, and allowed non-authoritative booking confirmations. | Introduced the authoritative `getTripSummary()` selector with explicit `usesSampleData` provenance flags, required travel dates before generating pricing, and isolated sandbox state. | [`tests/unit/test_tripSummaryHelper.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/unit/test_tripSummaryHelper.ts), [`tests/unit/test_phase1_verification.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/unit/test_phase1_verification.ts) |
| **Phase 1** (Data Leaks & Domestic Isolation) | Domestic Indian itineraries leaked mock artifacts from Vietnam/Hanoi (HAN, Noi Bai), hardcoded guest names (Sharma, Rahul), and false "4 Seats Confirmed" claims. | Purged all hardcoded international strings from domestic search and booking payloads; implemented comprehensive regex leak guards across all consumer UI views. | [`tests/unit/test_phase1_verification.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/unit/test_phase1_verification.ts) (35 checks), [`tests/e2e/e2e_scenarios.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/e2e/e2e_scenarios.ts) (Leak Guard across 6 screens) |
| **Phase 2** (Honest Sandbox & Data Provenance) | Simulated checkout flows lacked transparent labeling, rapid double-clicks created duplicate bookings, and marketing text used unsubstantiated guarantees ("100% verified", "Best price guaranteed") and asked for payment credentials. | Labeled all sandbox entities `SIMULATED BOOKING · SANDBOX` with explicit disclaimers ("no tickets were issued and nothing was charged"); built idempotent submission controller; purged false guarantees and card CVV inputs. | [`tests/unit/test_phase2_verification.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/unit/test_phase2_verification.ts) (32 checks), [`tests/e2e/e2e_scenarios.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/e2e/e2e_scenarios.ts) (Scenario 5 double-click idempotency) |
| **Phase 3** (Deterministic Budget Allocator) | LLM calculated non-deterministic floating-point totals that drifted; arrival airport selection ignored ground travel drive times to hotel zones; luxury upgrades lacked concrete budget offsets. | Built deterministic integer-rupee budget allocator (`TripPlanningEngine`); implemented airport route optimization selecting Dabolim (GOI) for South Goa and Mopa (GOX) for North Goa based on drive times; provided concrete balancing options (fewer nights, rail) with computed rupee impacts. | [`tests/unit/test_phase3_verification.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/unit/test_phase3_verification.ts) (61 checks), [`tests/e2e/e2e_scenarios.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/e2e/e2e_scenarios.ts) (Scenario 1 & Scenario 3) |
| **Phase 3.1** (Financial Corrections & Rule Completeness) | Flight packages only covered outbound legs; food tier rules lacked documented downgrade transparency; cab days were billed indiscriminately; fictional trains were suggested; unverified knowledge docs claimed live verification. | Updated flight packages to cover round trips (outbound + return, e.g. IX 924 / IX 925); documented food-tier downgrade rule with 'assumed' note; billed local cabs only on days with excursions; verified rail catalog routes before offering trains; labeled knowledge docs with "Source: {domain}"; formatted buffers as "₹X left in your budget". | [`tests/unit/test_phase3_verification.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/unit/test_phase3_verification.ts) (Full line-item audit and invariant suite) |
| **Phase 4** (Visual & UX Redesign) | Monolithic 2,600-line dashboard component had excessive dark visual weight and did not reflect the light, calm, consumer-friendly prototype design. | Redesigned consumer journey into a 5-step flow (`DescribeScreen`, `ClarifyScreen`, `PlanScreen`, `CheckoutBookingFlow`, `BookingConfirmationView`, `MyTripsView`) using Figma prototype tokens (`#F5F6F3` background, `#0E6B59` emerald, Bricolage Grotesque / Figtree typography); decomposed dashboard into 7 focused subcomponents. | Visual regression verification, [`tests/e2e/e2e_scenarios.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/e2e/e2e_scenarios.ts) (Scenarios 1–4) |
| **Phase 5** (E2E Tests, Accessibility & Mobile Audit) | Absence of automated browser test suite; accessibility contrast and label-in-name mismatches on interactive elements; potential horizontal scroll issues at 375px mobile viewport. | Created automated browser E2E test suite with axe-core audits (0 critical/serious violations across all 6 views), keyboard-only navigation verification, and strict 375px viewport boundary assertions (`scrollWidth <= 375px`); organized tests into `/tests/unit` and `/tests/e2e`; updated esbuild peer dependencies. | [`tests/e2e/e2e_scenarios.ts`](file:///c:/Users/aswin/.antigravity-ide/AeroDAG/tests/e2e/e2e_scenarios.ts) (90/90 PASSED), `npm run test:all` (230/230 PASSED) |
